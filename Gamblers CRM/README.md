# Gamblers CRM

Аналитика потока по трейдингу: откуда приходит трафик, кто доживает до конца обучения
и кто реально общается в Telegram-чате.

Первая версия — только аналитика. Продажи, платежи и рассылки сюда пока не входят.

## Что считает

| Раздел | Вопрос, на который отвечает |
|---|---|
| **Обзор** | Сколько людей в группе, приток и отток по дням, что стало с пришедшими за период, из чего состоит аудитория |
| **Источники** | Какой блогер/закуп приводит людей, которые остаются и говорят, а не просто вступают. Цена входа по расходу |
| **Удержание** | Когорты по неделе вступления: доля доживших на 1/3/7/14/30/60-й день и доля пишущих на N-й неделе жизни |
| **Активность** | Когда чат живой (день недели × час), объём общения, кто держит чат |
| **Люди** | Поимённо: сегмент, источник, стаж, сообщения. Карточка человека с историей |
| **Настройки** | Подключение Telegram, источники трафика, привязка пригласительных ссылок |

Сегменты участника: **Ядро** (10+ сообщений за 14 дней), **Активные** (1–9), **Засыпают**
(писали раньше, молчат дольше порога), **Молчуны** (ни одного сообщения), **Ушли**.
Пороги меняются в `.env` (`CORE_MESSAGES`, `INACTIVE_DAYS`).

## Стек

Next.js 15 (App Router, серверные компоненты) · TypeScript · PostgreSQL + Prisma ·
GramJS (MTProto) для сбора из Telegram. Графики — свой SVG, без графических библиотек.

## Быстрый старт

```bash
cp .env.example .env          # укажите DATABASE_URL
npm install
npm run db:push               # создать схему
npm run db:seed               # демо-данные, чтобы посмотреть дашборд без Telegram
npm run dev                   # http://localhost:3000
```

Демо-данные помечены `[demo]` и `demo-*`; повторный `db:seed` их пересоздаёт. Перед
подключением боевого чата снесите их: удалите демо-чат в БД или выполните `db:push --force-reset`.

## Подключение Telegram

Сбор идёт под **личным аккаунтом** через MTProto: он видит историю чата, вступления
и выходы. Аккаунт должен состоять в группе; для атрибуции по ссылкам — быть её админом.

1. На <https://my.telegram.org> → API development tools получите `api_id` и `api_hash`,
   впишите в `.env` вместе со списком чатов:

   ```
   TG_API_ID="123456"
   TG_API_HASH="…"
   TG_CHATS="@my_trading_chat,-1001234567890"
   ```

2. Вход (один раз, спросит телефон, код и пароль 2FA):

   ```bash
   npm run tg:login       # строка сессии сохранится в .env как TG_SESSION
   ```

3. Первая выгрузка истории — может идти долго на большом чате:

   ```bash
   npm run tg:backfill
   ```

4. Догрузка нового — в крон раз в 10–15 минут:

   ```bash
   npm run tg:sync
   ```

   ```cron
   */10 * * * * cd /path/to/Gamblers\ CRM && /usr/bin/npm run tg:sync >> /var/log/gamblers-sync.log 2>&1
   ```

### Что откуда берётся

| Данные | Источник в Telegram | Нужны права админа |
|---|---|---|
| Сообщения и авторы | история чата | нет |
| Текущий состав, дата вступления | список участников | нет |
| Выходы | сверка состава между выгрузками + служебные сообщения | нет |
| Вступления и выходы с точным временем | журнал администратора | **да** |
| По какой ссылке пришёл человек | журнал администратора + список ссылок | **да** |

Без прав администратора всё считается, кроме атрибуции: такие люди попадают в строку
«Без метки», а время выхода определяется с точностью до запуска синхронизации.

## Атрибуция трафика

Одна пригласительная ссылка = один источник. Схема работы:

1. В Telegram создайте отдельную ссылку под каждый источник (блогер, креатив, посев).
2. Коллектор подтянет ссылки в раздел **Настройки → Пригласительные ссылки**.
3. Заведите источник (и расход по нему) и выберите его в выпадающем списке напротив ссылки.
   Привязка сразу переносится на всех, кто уже пришёл по этой ссылке.

## Приватность

- `TG_SESSION` — это полноценный доступ к аккаунту. Лежит в `.env`, который не коммитится.
- Тексты сообщений по умолчанию **не хранятся**: только длина, число слов, наличие медиа
  и признак вопроса. Включить хранение первых 200 символов — `STORE_MESSAGE_PREVIEW="true"`.

## Структура

```
prisma/schema.prisma      модель данных (чаты, люди, участия, события, сообщения, источники)
prisma/seed.ts            генератор демо-данных
src/app/                  страницы дашборда (серверные компоненты)
src/components/charts/    графики: SVG, подсказки при наведении, светлая и тёмная темы
src/lib/metrics.ts        все метрики одним модулем: SQL-запросы к Postgres
src/collector/            выгрузка из Telegram: login, backfill, sync
```

Метрики считаются живыми запросами по сырым событиям — предагрегатов нет намеренно,
пока объёмы это позволяют (десятки тысяч сообщений считаются мгновенно).
