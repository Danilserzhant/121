# Gamblers CRM

Аналитика потока по трейдингу: откуда приходит трафик, кто доживает до конца обучения
и кто реально общается в Telegram-чате.

Первая версия — только аналитика. Продажи, платежи и рассылки сюда пока не входят.

## Что считает

| Раздел | Вопрос, на который отвечает |
|---|---|
| **Обзор** | Сколько людей в группе, приток и отток по дням, что стало с пришедшими за период, из чего состоит аудитория |
| **Источники** | Какой блогер/закуп приводит людей, которые остаются и говорят, а не просто вступают. Цена входа по расходу |
| **Удержание** | Когорты по неделе вступления: доля доживших на 1/3/7/14/30/60-й день и доля пишущих на N-й неделе жизни |
| **Активность** | Когда чат живой (день недели × час), объём общения, кто держит чат |
| **Люди** | Поимённо: сегмент, источник, стаж, сообщения. Карточка человека с историей |
| **Настройки** | Подключение Telegram, источники трафика, привязка пригласительных ссылок |

Сегменты участника: **Ядро** (10+ сообщений за 14 дней), **Активные** (1–9), **Засыпают**
(писали раньше, молчат дольше порога), **Молчуны** (ни одного сообщения), **Ушли**.
Пороги меняются в `.env` (`CORE_MESSAGES`, `INACTIVE_DAYS`).

## Стек

Next.js 15 (App Router, серверные компоненты) · TypeScript · PostgreSQL + Prisma ·
GramJS (MTProto) для сбора из Telegram. Графики — свой SVG, без графических библиотек.

## Быстрый старт

```bash
cp .env.example .env          # укажите DATABASE_URL
npm install
npm run db:push               # создать схему
npm run db:seed               # демо-данные, чтобы посмотреть дашборд без Telegram
npm run dev                   # http://localhost:3000
```

Демо-данные помечены `[demo]` и `demo-*`; повторный `db:seed` их пересоздаёт. Перед
подключением боевого чата снесите их: удалите демо-чат в БД или выполните `db:push --force-reset`.

## Подключение аккаунта: одна команда

Вход в Telegram не зависит от того, где потом будет жить CRM: строка сессии переносимая.
Проще всего пройти всё в браузере, через GitHub Codespaces — на компьютер ничего не ставится.

1. В репозитории: **Code → Codespaces → Create codespace**. Зависимости встанут сами.
2. В терминале:

   ```bash
   cd "Gamblers CRM"
   npm run setup
   ```

Мастер проведёт по четырём шагам и всё запишет в `.env`:

1. **Аккаунт** — спросит `api_id`/`api_hash` (берутся на <https://my.telegram.org> →
   API development tools), затем телефон, код из Telegram и пароль 2FA.
2. **Чаты** — покажет нумерованный список ваших групп с числом участников и правами,
   вы называете номера. Если прав администратора нет — предупредит, что источники
   останутся «Без метки».
3. **База** — спросит `DATABASE_URL` (бесплатно и без карты: <https://neon.com>) и создаст таблицы.
4. **Выгрузка** — вытянет историю: участников, сообщения, вступления и выходы.

После этого `npm run dev` — и дашборд открывается на ваших данных.

Код из Telegram и строку `TG_SESSION` не пересылайте никому: этого достаточно, чтобы
войти в аккаунт. Отдельные шаги, если нужно по частям: `npm run tg:login`,
`npm run tg:chats`, `npm run tg:backfill`, `npm run tg:sync`.

## Как устроен сбор данных

Работает под **личным аккаунтом** через MTProto: он видит историю чата, состав и выходы.
Аккаунт должен состоять в группе; для атрибуции по ссылкам — быть её администратором.

| Данные | Источник в Telegram | Нужны права админа |
|---|---|---|
| Сообщения и авторы | история чата | нет |
| Текущий состав, дата вступления | список участников | нет |
| Выходы | сверка состава между выгрузками + служебные сообщения | нет |
| Вступления и выходы с точным временем | журнал администратора | **да** |
| По какой ссылке пришёл человек | журнал администратора + список ссылок | **да** |

Без прав администратора считается всё, кроме атрибуции: такие люди попадают в строку
«Без метки», а время выхода определяется с точностью до запуска синхронизации.

Держать данные свежими: `npm run tg:sync` по расписанию — в кроне, в docker compose
или в GitHub Actions (см. ниже).

```cron
*/10 * * * * cd /path/to/Gamblers\ CRM && /usr/bin/npm run tg:sync >> /var/log/gamblers-sync.log 2>&1
```

## Атрибуция трафика

Одна пригласительная ссылка = один источник. Схема работы:

1. В Telegram создайте отдельную ссылку под каждый источник (блогер, креатив, посев).
2. Коллектор подтянет ссылки в раздел **Настройки → Пригласительные ссылки**.
3. Заведите источник (и расход по нему) и выберите его в выпадающем списке напротив ссылки.
   Привязка сразу переносится на всех, кто уже пришёл по этой ссылке.

## Запуск в Docker

Для сервера: поднимает базу, дашборд и коллектор одной командой.

```bash
cp .env.example .env      # заполните POSTGRES_PASSWORD, TG_API_ID, TG_API_HASH, TG_CHATS
docker compose up -d --build
docker compose run --rm collector npm run tg:login   # вход в Telegram, сессия пишется в .env на хосте
docker compose run --rm collector npm run tg:backfill # первая выгрузка истории
```

Дашборд поднимется на `WEB_PORT` (по умолчанию 3000), схема накатится при старте,
коллектор будет догружать новое каждые `SYNC_INTERVAL` секунд. `DATABASE_URL` внутри
compose собирается автоматически — в `.env` его задавать не нужно.

Образ собирается из этого же репозитория и запускает ровно то, что проверено локально
(`npm ci` → `prisma generate` → `next build` → `npm start`); сама сборка образа в среде
разработки не прогонялась — Docker Hub не отдавал базовый образ.

## Бесплатный хостинг

Два рабочих варианта — оба проверялись по актуальным условиям площадок.

### А. Без карты и без сервера

| Часть | Где | Условия |
|---|---|---|
| База | [Neon](https://neon.com/pricing) или Supabase | 0.5 ГБ, карта не нужна |
| Дашборд | [Render](https://render.com/docs/free), free web service | засыпает после 15 мин простоя, просыпается ~за минуту |
| Коллектор | GitHub Actions, `.github/workflows/tg-sync.yml` | раз в час, 2000 бесплатных минут в месяц на приватном репозитории |

Порядок:

1. Заведите базу в Neon, скопируйте строку подключения (с пулингом).
2. На Render: **New → Blueprint**, укажите этот репозиторий — `render.yaml` уже лежит рядом.
   В переменных задайте `DATABASE_URL`.
3. Локально один раз войдите в Telegram (`npm run tg:login`) и скопируйте `TG_SESSION` из `.env`.
4. В GitHub: **Settings → Secrets and variables → Actions** → секреты `DATABASE_URL`, `TG_API_ID`,
   `TG_API_HASH`, `TG_SESSION`; переменная `TG_CHATS`.
5. Вкладка **Actions** → *Telegram sync* → **Run workflow** → `backfill` (первая выгрузка),
   дальше он сам идёт раз в час.

Что важно знать про этот вариант:

- `TG_SESSION` в секретах GitHub — это доступ к аккаунту. Репозиторий должен быть приватным,
  а доступ к нему — только у вас.
- Час — осознанный интервал: у бесплатной базы лимит рабочих часов, а чаще для аналитики и не нужно.
- Расписания в Actions отключаются после 60 дней без активности в репозитории — Github пришлёт письмо.
- Бесплатный тариф Render — для личных проектов; для коммерческого потока честнее вариант Б.

### Б. Свой сервер, всё в одном

[Oracle Cloud Always Free](https://www.oracle.com/cloud/free/) даёт постоянно бесплатную ARM-машину
(2 ядра, 12 ГБ) — карта нужна только для верификации, списаний нет. Подойдёт и любой VPS от $5.
Дальше — раздел «Запуск в Docker» выше: база, дашборд и коллектор поднимаются одной командой,
ничего не засыпает, синхронизация может идти каждые 10 минут.

## Приватность

- `TG_SESSION` — это полноценный доступ к аккаунту. Лежит в `.env`, который не коммитится.
- Тексты сообщений по умолчанию **не хранятся**: только длина, число слов, наличие медиа
  и признак вопроса. Включить хранение первых 200 символов — `STORE_MESSAGE_PREVIEW="true"`.

## Структура

```
prisma/schema.prisma      модель данных (чаты, люди, участия, события, сообщения, источники)
prisma/seed.ts            генератор демо-данных
src/app/                  страницы дашборда (серверные компоненты)
src/components/charts/    графики: SVG, подсказки при наведении, светлая и тёмная темы
src/lib/metrics.ts        все метрики одним модулем: SQL-запросы к Postgres
src/collector/            выгрузка из Telegram: login, backfill, sync
```

Метрики считаются живыми запросами по сырым событиям — предагрегатов нет намеренно,
пока объёмы это позволяют (десятки тысяч сообщений считаются мгновенно).
